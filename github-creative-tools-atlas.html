一、绘画 / 数字绘图

从纯手绘到 AI 辅助，画笔这一端的地基

这一区可以分成两派：「手绘派」讲究笔刷、图层、逐帧控制（Krita、Aseprite、OpenToonz）；「生成派」把 AI 变成可编排的流水线（ComfyUI）。中间那座桥就是 krita-ai-diffusion——它让 AI 待在画师的画布里，而不是让画师跑去 AI 的网页里。ControlNet 则是"姿势 / 线稿可控"这项能力的源头，虽然原仓库已封存。

ComfyUI

github.com/Comfy-Org/ComfyUI
147.1k ★活跃
功能节点式生成工作流引擎，把模型、预处理器、采样、输出连成可复用的图；图像 / 视频 / 3D / 音频皆可编排，支持自定义节点与 API 化部署。
场景角色立绘与三视图批量生成、线稿上色、风格迁移、给下游 3D 生成准备干净的输入图。
热度17.6k forks，最新提交 2026-11-15；GPL-3.0。整个开源创作生态事实上的"中枢神经"。
推荐理由：如果只深入一个 AI 项目，选它。它不只是画图工具，更是后面 AI 3D、纹理生成、插件后端的共同底座（krita-ai-diffusion 就拿它当后端）。注意仓库已迁至 Comfy-Org 组织，旧地址 comfyanonymous/ComfyUI 会跳转。
GPL-3.0Python需 GPU生态中心

Krita

github.com/KDE/krita
10.8k ★活跃
功能专业级开源数字绘画软件：笔刷引擎、图层 / 蒙版、色彩管理、动画时间轴、漫画分格与透视辅助、Python 插件。
场景插画、概念设计、漫画、贴图绘制；也是画角色设定稿与三视图的主力工具。
热度917 forks，最新提交 2026-11-16（调研当日仍有提交）；GPL-3.0。GitHub 为镜像，主仓在 KDE Invent。
推荐理由：免费里最接近"正经画画"的那个，社区教程与笔刷资源海量，且是 AI 插件的宿主。想走「立绘 → 手办」路线，它是链条第一环最稳妥的起点。
GPL-3.0C++ / Qt桌面端零成本入门

Krita AI Diffusion

github.com/Acly/krita-ai-diffusion
10.9k ★活跃
功能Krita 内的生成式 AI 插件：选区局部重绘 / 扩图、Live Painting 实时反馈、线稿与姿态控制、分区域提示词、4K/8K 放大；后端为 ComfyUI，可本地可云端。
场景边画边改角色设定、快速试配色与构图、给草稿补细节，而不打断绘画手感。
热度657 forks，83 个 release，最新提交 2026-10-03，v1.53.0（2026-08）。仍在跟进 Krita 6 / Qt6。
推荐理由：这是"AI 辅助绘画"最舒服的形态——笔刷还是笔刷，AI 只是图层。对画师比独立 WebUI 友好得多，也天然衔接后面生成 3D 所需的干净立绘。建议 ≥6GB 显存。
插件Python建议 6GB+ 显存

Aseprite

github.com/aseprite/aseprite
~40.8k ★活跃
功能像素画与逐帧动画编辑器：图层 / 帧分离、洋葱皮、调色板、像素完美笔刷、精灵表导出、Lua 脚本。
场景像素角色、游戏精灵、低成本角色设定草稿，以及像素风周边 / 拼豆图纸。
热度约 9.4k forks，2026 年持续高频发布（v1.3.18.x 系列），近 30 天仍稳定涨星。
推荐理由：像素画领域无可争议的标准件，工具完成度极高。但要看清许可证：源码可读、可自行编译，官方二进制为商业授权（EULA），商用请购买或改用 LibreSprite / Pixelorama。
EULA / 源码可见C++许可证需注意

OpenToonz

github.com/opentoonz/opentoonz
7.8k ★活跃
功能完整 2D 动画制作软件：扫描线稿、自动上色、摄影表、骨骼 / 变形、特效节点、渲染输出。
场景传统赛璐璐动画、角色动作稿、动态立绘；也可当作批量线稿清理工具。
热度893 forks，2026-11 仍有提交，稳定低速维护；源自吉卜力使用过的 Toonz。
推荐理由：免费、专业、血统正。若你的"角色"不止是静态立绘，而是想让它动起来，这是开源里少有的完整工业流程，值得为特定需求单独深入。
C++桌面端动画流程

ControlNet

github.com/lllyasviel/ControlNet
34.1k ★原仓停更
功能给扩散模型加"条件控制"：姿态骨架、线稿、Canny 边缘、深度图、法线、分割，让生成结果服从你画的结构。
场景固定角色姿势、按草稿生成上色稿、生成一致的多视图 / 三视图（AI 3D 的关键前置）。
热度3k forks，Apache-2.0；最后推送 2024-02-25，原仓库已冻结，但技术被 ComfyUI 生态与各模型作者完整继承。
推荐理由：把它当"必读经典 + 概念地图"，而不是要 clone 的代码。理解它，才知道为什么三视图生成、姿势控制能成。实际使用请走 ComfyUI 的 ControlNet / Union 节点与新版权重。
Apache-2.0奠基性论文勿直接部署

延伸坐标（同类可选）

  • excalidraw/excalidraw · 手绘风白板，适合画流程草图与创作构思，不是正式绘画工具。
  • openpose（~33.6k ★）· 姿态关键点提取，做角色姿势参考；同样已停更多年。
  • AUTOMATIC1111/stable-diffusion-webui 与 Fooocus · 上一代 AI 绘画界面的王者，如今节奏明显放缓，新项目更建议从 ComfyUI 起步。
  • armory3d/armorpaint（~5.5k ★）· 直接在 3D 模型表面绘制 PBR 贴图，是"绘画"与"建模"之间的那道门。

二、3D 建模

从手雕多边形，到用一句话指挥软件

这区的分野很有意思：Blender 系负责有机造型与艺术创作，FreeCAD / OpenSCAD 系负责尺寸精确的零件（手办底座、支架、连接件），trimesh / assimp 是不出镜但决定成败的"管道工"——格式混乱、模型漏面、打印失败，全靠它们收拾。2026 年最大变量是 MCP / Agent 驱动建模：不用记菜单，用自然语言指挥 Blender。

Blender

github.com/blender/blender
~21.7k ★活跃
功能全流程 3D 创作套件：建模、雕刻、重拓扑、UV、材质、骨骼绑定、动画、模拟、渲染、合成、Grease Pencil 2D 绘制。
场景角色造型、手办修模拆件、AI 生成网格的清理、渲染展示图；几乎每条路线的必经站。
热度GitHub 为官方镜像（主开发在 projects.blender.org），2026-11 仍有更新；GPL-3.0。星数不高只是因为主仓不在 GitHub。
推荐理由：不用犹豫的"大陆架"。插件生态（VRM、MMD、glTF、MCP、Hunyuan3D）全都围着它转，学会它等于同时解锁其他十个项目。注意 clone 时用 GIT_LFS_SKIP_SMUDGE=1。
GPL-3.0C++必学地基GitHub 为镜像

MCP for Blender

github.com/ahujasid/mcp-for-blender
34.5k ★活跃
功能MCP 服务端 + Blender 插件，让 LLM 直接读写场景：建物体、改材质、打光、渲染、执行 bpy 脚本、导入资产、调用图生 3D 服务。
场景零基础搭场景、批量重复操作自动化、把"一句话描述"变成可继续编辑的 Blender 工程。
热度3.1k forks，MIT，最新提交 2026-11-13；2025–2026 涨势最猛的 3D 类项目之一。2026-09-16 由 blender-mcp 改名，旧链接仍可跳转。
推荐理由：代表了 2026 年最值得押注的新范式——AI 不是替你出图，而是替你操作软件。想判断"要不要投入 Agent 化创作"，从它试最省事。注意它会执行任意 Python，别在不可重建的工程上跑无人值守任务。
MITPython2026 新范式注意改名

FreeCAD

github.com/FreeCAD/FreeCAD
35.4k ★活跃
功能参数化 3D CAD：约束草图、特征历史、工程图、Python API；基于 OpenCASCADE，含 BIM / FEM / CAM 工作台。
场景手办底座、支撑桩、可动连接件、亚克力立牌、尺寸必须精确的机械件。
热度2026-11-12 有更新，1.1.4 版本；LGPL-2.1。开源 CAD 里星数最高、社区最厚。
推荐理由：Blender 擅长"好看"，FreeCAD 擅长"能装得上"。做实体手办时，尺寸精度决定成败，两者互补而不是二选一。
LGPL-2.1C++ / Python工程精度

OpenSCAD

github.com/openscad/openscad
10.6k ★活跃
功能用代码描述实体：构造实体几何（CSG）+ 2D 轮廓拉伸，改一个变量整件模型随之重算；导入导出 DXF / STL / OFF。
场景批量参数化配件、可复用的底座模板、需要 Git 版本管理与自动生成的设计。
热度2026-11-13 仍有提交；GPL-2.0。稳定版号偏旧但代码库持续维护。
推荐理由：程序员思维做实体的最优解——模型即代码，可 diff、可复用、可批量出 100 个尺寸。和 AI 编码助手搭配尤其顺手。
GPL-2.0C++代码化建模

trimesh

github.com/mikedh/trimesh
3.7k ★活跃
功能纯 Python 三角网格库：STL / OBJ / PLY / GLB / 3MF 读写，水密性检查、法线修复、布尔运算、体素化、截面切片、体积与质心计算。
场景AI 生成模型的自动体检与修补、打印前检查是否漏面、批量格式转换、写自己的模型处理脚本。
热度703 forks，MIT，最新推送 2026-11 上旬；PyPI 周下载量数百万，是机器人 / 3D 打印领域的隐形基础设施。
推荐理由：星数不起眼，实用度极高。AI 生 3D 到能打印之间最常卡住的就是"网格不水密"，十几行 trimesh 代码就能自动体检并修一部分；只依赖 numpy，装上就能用。
MITPython打印前必查轻量

Assimp

github.com/assimp/assimp
13.3k ★活跃
功能Open Asset Import Library：把 40+ 种 3D 格式（FBX / glTF / OBJ / STL / Collada / 3MF…）读进统一内存结构，附带三角化、法线生成、去重等后处理；C/C++ API 与多语言绑定。
场景模型资源互通、写导入器 / 查看器、把网上下载的角色模型转进自己的管线。
热度3.3k forks，最新提交 2026-11-13，v6.0.5；15 年持续维护的老牌库。被无数引擎与工具间接依赖。
推荐理由：角色模型圈的格式混乱是常态（PMX、FBX、VRM、GLB…）。Assimp 是那条最成熟的"万能翻译官"管道，做工具开发时省下大量解析工作。
C++库 / 非 GUI格式互通

延伸坐标（按需取用）

  • CadQuery/cadquery（6.1k ★）· Python 版参数化 CAD，比 OpenSCAD 更贴近现代 Python 工作流。
  • MeshLab（5.7k ★）· 网格清理、修补、简化、贴图烘焙的图形界面老将，3D 打印前处理常用。
  • instant-meshes（6.1k ★）· 自动四边面重拓扑；AI 生成的一团三角面想变成可编辑的规整网格就靠它（另有社区现代化分支 instant-meshes-2026）。
  • earthtojake/text-to-cad（~26k ★，2026 新项目）· 给编码 Agent 用的 CAD 技能包，代表"Agent 驱动建模"的另一条支线。

三、AI 图生 3D（传送门）

把一张角色立绘，吹成一个可旋转的网格

这是 2024–2026 变化最剧烈的星区，也是"绘画 → 手办"最短的那座桥。判断标准不再是"能不能生成"，而是三件事：有没有 PBR 贴图、网格是否水密可打印 / 可导入引擎、许可证能不能商用。按显存从低到高：TripoSR（约 6GB）→ Hunyuan3D-2 / TRELLIS（10–16GB）→ TRELLIS.2（24GB）。

Hunyuan3D 2.0

github.com/Tencent-Hunyuan/Hunyuan3D-2
15.4k ★生态最厚
功能两阶段生成：Hunyuan3D-DiT 先出无纹理几何，Hunyuan3D-Paint 再合成高分辨率贴图；支持单图 / 多视图 / 文本，输出 GLB、OBJ，带本地 API 与 Blender 插件，另有 mini 版。
场景把动漫角色立绘直接变成可打印手办雏形、道具摆件快速原型；2.1 版本进一步产出生产级 PBR 材质。
热度该方向星数最高的开源项目；另有 Hunyuan3D-2.1（~4.4k ★）与 Windows 整合包。ComfyUI / Blender 生态适配最全。
推荐理由：中文资料最多、周边最全、上手路径最短，适合作为"第一次把立绘变 3D"的入口。但许可证是社区许可（排除 EU/UK/韩国，超 100 万 MAU 需另申请），商用务必先读 LICENSE。全流水线约需 10–29GB 显存。
社区许可 · 有地域限制PBR 贴图GLB / OBJ10GB+ 显存

TRELLIS / TRELLIS.2

github.com/microsoft/TRELLIS · /TRELLIS.2
14.3k ★活跃
功能初代用结构化潜变量 SLAT，一份结果可解码成 Mesh / 3D Gaussian / Radiance Field，支持文本与图像输入、局部编辑与变体生成；TRELLIS.2（4B，O-Voxel）主打任意拓扑与含透明度的完整 PBR。
场景游戏资产（Mesh）、网页实时展示（Gaussian）、高保真带材质手办原型；同一原型多格式复用。
热度TRELLIS 14.3k ★（CVPR'25 Spotlight），TRELLIS.2 约 12.9k ★（2025-12 发布，9 个月破万），2026 年仍在更新。
推荐理由：许可证最干净（MIT）、细节上限最高，是想认真做资产或商用的首选。代价是门槛：初代约 16GB 显存 / Linux，TRELLIS.2 需 24GB，且 2 代仅支持单图输入、 texte-to-3D 与 Gaussian 输出仍留在初代。
MITCVPR'25多格式输出16–24GB 显存

TripoSR

github.com/VAST-AI-Research/TripoSR
6.9k ★维护平缓
功能前馈式单图 3D 重建：Transformer 大重建模型直接从图像特征预测 triplane NeRF 并抽网格，官方数据 A100 上不到 0.5 秒。
场景快速验证创意、批量草稿、作为自己工具的基座模型；低配显卡也能跑。
热度MIT，约 6GB 显存且可 CPU 回退；仓库本身更新不频繁，但被大量下游项目当作底层依赖。
推荐理由：论质量它已经不是 SOTA，但论"跑得起来"它无敌：纯 MIT、无附加条款、消费级显卡可用。想先花一小时验证"图生 3D 到底能不能用"，从它开始最不容易劝退；想做二次开发也最省心。
MIT · 无附加条款~6GB 显存<0.5s仅顶点色

InstantMesh

github.com/TencentARC/InstantMesh
~4.6k ★已放缓
功能多视图扩散 + 稀疏视图大重建模型，用 FlexiCubes 替代 marching cubes，得到面分布更规整的可编辑网格；单图输入。
场景学习"多视图 → 网格"的经典架构；需要相对规整拓扑的原型。
热度508 forks，Apache-2.0；主要提交集中在 2024 年，近两年维护缓慢，星数仍缓慢增长。
推荐理由：架构干净、许可证宽松（Apache-2.0），至今是最容易读懂的单图生网格教学样本。但别把它当 2026 的生产工具——这是"星数高 ≠ 还活着"的典型案例，实用请优先 Hunyuan3D / TRELLIS。
Apache-2.0教学价值高维护缓慢

Unique3D

github.com/AiuniAI/Unique3D
3.6k ★维护平缓
功能单图约 30 秒产出带纹理网格：多视图扩散生成一致视角 → 多级上采样提纹理 → ISOMER 即时网格重建。
场景桌面摆件照片快速数字化、卡通 / 写实小物件的快速原型。
热度NeurIPS 2024，约 3.6k ★；最后集中更新在 2025 年，家用显卡相对友好。
推荐理由：速度与质量的折中点，对显存不宽裕、又想要贴图的人很实用。适合作为"第二台发动机"对比体验，不建议作为长期主栈。
NeurIPS'24约 30s带纹理

选型速查 · 三台发动机

按你的显卡与用途对号入座
对照表
6GBTripoSR — 最快、纯 MIT、只有顶点色；适合验证想法与二次开发。

四、手办 / 角色模型

从虚拟形象，到握在手里的实体

这一区是"角色"真正落地的地方，分成两条支线：数字角色（MakeHuman 造人体 → VRM 标准 → 网页展示）与 实体手办（切片 → 光固化修复 → 打印）。中间还需要格式转换与重拓扑。星数普遍不高，但每一个都卡在流水线的关键节点上，属于"小而不可替代"。

MakeHuman

github.com/makehumancommunity/makehuman
~1.6k ★活跃
功能用滑杆生成参数化 3D 人体：体型、五官、年龄、性别、姿态可调，输出带骨骼的基础网格；Python + 插件体系，配套社区资产库。
场景角色建模起点、人体比例参考、快速做可继续雕刻的 base mesh，避免从球体开始拉人。
热度296 forks；近 30 天 +73 星，2026-11 仍在 trending 榜上，属于"老项目回温"。
推荐理由：做角色手办最费时间的就是人体基础形。它把这一步压缩成几分钟，且完全开源可改。配合 MPFB2（Blender 插件）或 VRM 插件，可以一路走到可动角色。
Python桌面端角色起点近期回温

VRM Add-on for Blender

github.com/saturday06/VRM-Addon-for-Blender
1.7k ★活跃
功能在 Blender 中导入 / 导出 VRM 0.x 与 1.0：Humanoid 骨骼映射（兼容 MMD / VRoid / Mixamo 命名）、MToon 材质、表情、物理、Python 自动化 API。
场景把 Blender 里做好的角色变成 VRM 虚拟形象；把现成 VRM 模型导入 Blender 改造、拆件、做手办。
热度170 forks，MIT，2026 年高频发版（v4.10.x，10–11 月），已跟进 Blender 5.x；维护健康度评分很高。
推荐理由：它是"角色模型圈通用语 VRM"与" Blender 工作流"之间最可靠的闸门。想让数字角色既能在网页 / VTuber 里动，又能拿去打印，这个插件几乎是必装。
MITBlender 插件VRM 1.0MToon

three-vrm

github.com/pixiv/three-vrm
2.3k ★活跃
功能Three.js 的 VRM 加载与渲染库：VRM 1.0 人形骨骼、表情 / 视线、MToon 卡通材质、SpringBone，兼容 WebGL 与 WebGPU。
场景网页 3D 角色展示页、作品集、在线模型预览器、轻量 VTuber 应用。
热度200 forks，MIT，2026-10 仍有更新，近 30 天 +63 星；由 pixiv 官方维护。
推荐理由：做完了角色，总得让人看见。它是把 .vrm 放进浏览器最省事、最正统的方式，配 model-viewer（看 GLB）基本能覆盖所有展示需求。
MITTypeScriptWeb 展示

CharacterStudio

github.com/M3-org/CharacterStudio
375 ★活跃
功能浏览器里的 VRM / glTF 角色工作室：点选式换装、拖入本地模型与贴图、调色、一键优化（合并蒙皮网格 / 图集合并）、批量导出 GLB / VRM。
场景不装 Blender 也能快速拼角色、做变体、给游戏 / 直播准备轻量化 avatar。
热度MIT，2026 年持续维护（含依赖安全更新），星数小但方向独特、提交频繁。
推荐理由：星数最低但最"好玩"的一个——它把捏人变成网页上的搭积木。如果你想先低成本体验"角色组装"再决定要不要啃 Blender，这是最轻的入口。
MITWeb / React低门槛

OrcaSlicer

github.com/OrcaSlicer/OrcaSlicer
~16.2k ★活跃
功能FDM 切片软件：内置校准测试、逐特征参数、树状 / 有机支撑、多材料与多机型配置（Bambu / Prusa / Voron / Creality 等）。
场景FDM 打印手办原型、大件分件、底座与支架；打印前的支撑与摆放策略。
热度约 2.1k forks，AGPL-3.0，v2.4.2（2026-07），2026-10 仍有提交；近四年星数反超 PrusaSlicer，成为切片区人气第一。
推荐理由：功能迭代最快、机型覆盖最广的开源切片器，手办打印的"最后一公里"。注意仓库已从 SoftFever 个人账号迁到 OrcaSlicer 组织；若只求稳定，PrusaSlicer（~9.4k ★）更保守，Cura（~7.1k ★）机型最杂食。
AGPL-3.0C++FDM注意组织迁移

UVtools

github.com/sn4k3/UVtools
~1.6k ★活跃
功能直接打开并编辑已切片的光固化文件（.ctb / .goo / .photon / SL1 等）：岛屿检测、吸盘 / 空腔检测、层修复、曝光校准生成器、机型格式互转，无需重新切片。
场景树脂打印精细手办前的"体检"：找出悬空孤岛、封闭空腔导致的爆裂风险，修好再打。
热度145 forks，AGPL-3.0，v7.1.x（2026-10/11），项目健康度评分优秀；光固化圈少有的长期活跃工具。
推荐理由：手办最吃细节，通常得用树脂机；而树脂打印最贵的不是树脂，是失败一整晚。它能在打印前把"注定失败"的文件挑出来，是这条路线里性价比最高的一颗小星。
AGPL-3.0C#MSLA / DLP失败预防

延伸坐标（角色生态的暗线）

  • PrusaSlicer（~9.4k ★）· 稳定保守的 FDM 切片；Cura（~7.1k ★）· 机型兼容最广。
  • glTF-Blender-IO（~1.7k ★）· GLB 进出 Blender 的官方通道，网页展示与引擎导入的标准格式。
  • vrm-c/vrm-specification · VRM 格式规范本身；VRMify · 把 MMD 的 PMX 模型转成 VRM（MMD 角色资源宝库的钥匙）。
  • VSeeFace · 面捕驱动 VRM 角色，让做好的形象动起来；smplx · 学术向参数化人体模型。

五、怎么选方向：三条走得通的航线

别按星数选，按"你想把时间花在哪"选

星数只说明"有多少人路过"，不说明"这条路适不适合你"。下面三条路线分别对应三种人：想画得更快的人、想让角色站起来的人、想造工具的人。

A

画师的数字工位

适合：插画 / 角色设定 / 想提升出图效率
Krita→krita-ai-diffusion→ComfyUI→ControlNet / 三视图

投入最小，见效最快。先在 Krita 里保持手绘手感，用插件做局部重绘与配色试验，需要批量与精细控制时再下沉到 ComfyUI 编排工作流。学完这条线，你已经顺手拥有了下游 AI 3D 所需的"干净立绘 + 一致三视图"能力。进阶可读 ControlNet 理解可控生成的原理。

B

一张立绘 → 一尊手办

适合：想做实体周边 / 手办原型
角色立绘 / 三视图→TripoSR 或 Hunyuan3D-2→Blender 修模拆件→trimesh 水密检查→UVtools / OrcaSlicer→打印

最有成就感，也最容易踩坑。低配先用 TripoSR 验证流程，追求贴图质量换 Hunyuan3D-2 或 TRELLIS；输出 GLB 后一定进 Blender 清理拓扑、补面、拆件，再用 trimesh 查水密；树脂机走 UVtools 查岛屿与吸盘，FDM 走 OrcaSlicer 排支撑。数字角色支线则把中段换成 MakeHuman → VRM 插件 → three-vrm 网页展示。

C

不画画，造工具

适合：开发者 / 想做管线与二次开发
trimesh + assimp→glTF / VRM 标准→three-vrm 前端→MCP for Blender→自己的插件 / Agent

天花板最高，2026 年最热。用 trimesh / assimp 处理几何与格式，用 three-vrm 做展示层，再用 MCP 把 LLM 接进 Blender。今年冒出的一批高星新项目（mcp-for-blender 34.5k、text-to-cad 26k、img2threejs 21k）都在证明同一件事："给创作软件装一个 Agent 接口"正在成为新的基础设施。如果你擅长写代码，这是最值得押注的方向。

六、出海前的四张警示图

星数会骗人，许可证和提交日期不会

1 · 许可证不是装饰品

Aseprite 是 EULA（源码可读，官方二进制需购买）；Hunyuan3D 用社区许可，明确排除欧盟 / 英国 / 韩国且有大用户条款；ComfyUI 是 GPL-3.0，OrcaSlicer / UVtools 是 AGPL-3.0（有网络服务传染性）；TRELLIS / TripoSR 是干净的 MIT。做周边售卖前，务必逐个读 LICENSE。

2 · 高星 ≠ 还活着

ControlNet 34.1k ★ 但最后推送 2024-02；InstantMesh 4.6k ★ 主要更新停在 2024；Fooocus、AUTOMATIC1111 也明显放缓。看 star 之前先看 pushed_at。经典仓库适合读原理，实际部署要找仍在维护的生态实现。

3 · 仓库会改名、会搬家

ComfyUI 已迁至 Comfy-Org/ComfyUI；blender-mcp 于 2026-09-16 更名 mcp-for-blender（旧链接仍跳转）；OrcaSlicer 从 SoftFever 迁到组织账号；Blender、Krita 在 GitHub 上只是镜像（主仓分别在 blender.org 与 KDE Invent）。收藏链接时记最新地址。

4 · 显存与"最后一公里"

图生 3D 从 6GB 到 29GB 不等，先量自己的显卡再选模型；没有本地卡可先用 Hugging Face Space 体验。另外，AI 直接吐出的网格通常不能直接打印：漏面、非流形、薄壁、内部空腔都得靠 Blender + trimesh + UVtools 收尾，这一步别省。

数据来源与口径：星数、fork、最近提交日期取自 2026-11-16 前后可访问的 GitHub 仓库页面（部分为实时读取）及 2026 年 10–11 月的公开统计快照（GitHub Topics、GitTrend、buildradar、git-stars 等）。星数会持续浮动，故多数以「约 / k」量级呈现，用于横向比较而非精确审计。

筛选原则：代表性（该方向绕不开）· 可用性（截至 2026-11 仍能运行）· 互补性（能串成完整链路）· 判断价值（能帮你决定要不要深入）。高星但已冻结的项目保留，并明确标注状态。
