# 创作工具星图 · 第八轮迭代记录（v1.7.0 → v1.8.0）

> 20 轮迭代，每轮明确目标 / 改动 / 理由 / 自检，均围绕一个质量维度做实质提升。
> 核心需求（9 条工作流 / 顶部选择 / 点击调用 / 任务包流入执行台）与整体结构全程稳定。
> 本轮的问题来自三路独立深度审查（HTML 运行时 10 + 桥接脚本 10 + 文档一致性 9 = 29 个真实缺陷），
> 与第七轮已修的 28 条零重叠。

## 迭代方式

第七轮修的是"静态代码缺陷"；本轮把鱼网撒向此前未照到的水域：
- 第一路：HTML 运行时行为（渲染性能、状态一致性、竞态、打印、畸形数据）；
- 第二路：桥接脚本实跑边界（HTTP 层、安装假成功、版本门槛、日志轮转）；
- 第三路：文档与交付一致性（数字失真、用户旅程断点、术语、遗留文件）。

## 阶段 A · 正确性（轮 1-6）

**轮 1 · 正确性** — 4 条支线的专用工具（ControlNet / ArmorPaint / Assimp / glTF-Blender-IO）因 roles 与 goalIds 无交集，被自己任务包的 `applicable()` 过滤掉，第3节说用、第4节却删。
改动：`profile()` 收集所有选中工作流 stages 点名的工具到 `stageTools`，`applicable()` 视为强制适用。自检：4 条支线的专用工具全部 applicable=true 且进入任务包。[达成]

**轮 2 · 边界情况** — localStorage 里 `h.p.workflows` 被篡改成非数组时 `renderExec` 的 `.map` 抛 TypeError，中断载入，按钮全禁用且控制台报错。
改动：`renderExec` 入口对 workflows/goals/subject/extra 做类型规范化；载入时 try/catch 降级。自检：5 种畸形数据（字符串/对象/null/undefined/正常）均不抛异常。[达成]

**轮 3 · 正确性** — `install-comfyui.ps1` 三条 pip 安装不检查退出码，torch 失败照样报"安装完成"。
改动：每条 pip 后检查 `$LASTEXITCODE`，失败 exit 1 并给针对性提示。自检：PS Parser 语法 OK，4 处退出码检查（clone + 3 pip）就位。[达成]

**轮 4 · 一致性** — 生成后改工作流/参数，输出区/执行台/保存仍是旧快照，无 dirty 提示，与"自动抓取"承诺相悖。
改动：`profileSig()` 签名比较，pick 与所有表单字段 input/change 触发 dirty；显示警示条并禁用 save/download。自检：改参数→警示出现+按钮禁用；重新生成→恢复。[达成]

**轮 5 · 正确性** — `callBridge` 持有按钮 DOM 引用，innerHTML 重绘后引用失效，finally 作用在游离节点上。
改动：改用 `pendingTools` 数据模型，重绘时按 id 渲染"处理中…"/disabled，去掉 DOM 引用依赖。自检：pending 期间按钮含 disabled 与"处理中"，移除后恢复。[达成]

**轮 6 · 健壮性** — HTTP POST body 不读 + protocol_version 未设，将来前端改 body 传参会请求解析错乱。
改动：do_POST 消费并丢弃 body（上限 64KB）；设 HTTP/1.1；OPTIONS 204 补 Content-Length。自检：临时端口实测带 body POST 后紧接 GET 正常，keep-alive 无残留。[达成]

## 阶段 B · 完整性与边界（轮 7-12）

**轮 7 · 性能** — 搜索框无 debounce，每次输入全量重建 500+ DOM 节点，中文输入法下卡顿。
改动：150ms debounce。自检：3 次快速输入→3 次 setTimeout(150ms)，前序被 clear。[达成]

**轮 8 · 完整性/交互** — renderBranches 全量重建吞掉用户手动折叠的支线与 details open 状态。
改动：折叠状态提升为数据（collapsedBranches / openFolds Set），渲染回放，切换更新数据，bswitch 同步 aria-expanded。自检：重绘后收起状态、aria-expanded=false、details open 全部回放。[达成]

**轮 9 · 正确性/竞态** — detectBridge async 不 await，连点刷新时旧 ping 结果覆盖新状态。
改动：`detecting` 互斥锁 + `detectGen` 代际计数，旧请求返回时若代际落后则丢弃。自检：三处关键代码（互斥/计数/淘汰）就位。[达成]

**轮 10 · 可读性** — print CSS 遗漏工作流卡片/支线/引导条，PDF 里浅字不可读、调试信息混入。
改动：打印时隐藏全部交互/引导区，只留任务包正文。自检：新选择器与标题隐藏规则就位。[达成]

**轮 11 · 完整性/可发现性** — 使用说明目录结构漏列 5 个脚本；README 的 `cd tools` 对 zip 用户无效（包里叫"快捷方式工具/"）。
改动：使用说明补齐 tool-bridge.py/启动器/安装脚本/说明文档/校验脚本；README 同时给"源码仓库 tools/"与"交付包 创作工具星图/快捷方式工具/"两种路径。自检：5 文件均列出，双路径说明就位。[达成]

**轮 12 · 性能/边界** — localStorage 存完整 text+prompt 冗余，save 无去重，连点 20 次撑满配额无提示。
改动：按内容签名去重（同源只更新时间）；超 20 条截断时提示"最旧 N 条已被覆盖"。自检：连点 2 次只留 1 条并提示"更新时间"；改内容后新增第 2 条。[达成]

## 阶段 C · 一致性与可读性（轮 13-17）

**轮 13 · 一致性/完整性** — selftest 的 README 版本检查路径硬编码，纯包环境运行时静默跳过，断言形同虚设。
改动：双路径解析（仓库/包），README 不可达时显式 FAIL 而非从 sources 静默消失。自检：新增"版本/README"检查 PASS，自检 23→24。[达成]

**轮 14 · 健壮性** — selftest 的 `read()` 无异常保护，缺文件时抛 traceback 而非结构化 FAIL。
改动：read() 捕获 OSError 返回空串并登记缺失列表；main 输出"读取/文件齐全"检查。自检：临时残缺包实测输出 `[FAIL] 读取/文件齐全 + SELFTEST_FAIL`，无 traceback。自检 24→25。[达成]

**轮 15 · 完整性** — build_manifest 单向校验，只确认清单内文件存在，不发现包内清单外文件。
改动：生成后反向全量扫描，发现清单外交付物即 sys.exit(1)。自检：放入 `_stray_test.txt` 被当场拒绝（EXIT=1），清理后恢复。[达成]

**轮 16 · 一致性/可读性** — 文档数字失真：README 断言数 22/17 矛盾、README 与使用说明"六轮120轮"漏第七轮、版本归属错标 v1.7.0 新特性。
改动：统一 25 条断言、7 轮 140 轮、版本归属改 v1.6.1/v1.6.2（v1.7.0 是质量加固）；补第七轮链接。自检：6 种失真表述零残留，README 链接零失效。[达成]

**轮 17 · 一致性** — CHANGELOG 断言数量时间线矛盾（17→22→新增5条仍22→23）。
改动：加"断言计数口径"脚注说明 check() 结果与子检查非简单加法；"新增 N 条"改"N 项检查"。自检：脚注与统一措辞就位。[达成]

## 阶段 D · 健壮性与可发现性（轮 18-20）

**轮 18 · 健壮性** — tool-bridge 无 Python 版本检查，PATH 上 python 指向 2.7/3.6 时秒退，启动器却提示"PATH 问题"，错误误导。
改动：main() 检查 `sys.version_info >= (3,7)`；PS 启动器失败提示带实际版本输出。自检：PS Parser 语法 OK，环境 Python 3.14.7 被正确识别。[达成]

**轮 19 · 边界/健壮性** — install-comfyui 的 bat 用 ASCII 编码，中文路径写坏；无 Python 版本门槛；日志无限增长。
改动：bat 改 UTF-8；加 Python 3.10+ 提示；日志超 1MB 轮转为 .log.1（保留一份）。自检：预置 1MB+ 日志触发轮转，备份 1048676 字节、新日志干净；install 脚本纯 ASCII。[达成]

**轮 20 · 可发现性/无障碍/完整性** — 首页工坊卡片停留 v1.6.0 描述（未提 9 支线/点击启动/执行台）；print 按钮从不禁用；release 目录遗留中文名旧包（哈希对不上）。
改动：首页卡片更新为当前能力；print 按钮纳入 dirty/reset/生成状态管理；删除遗留 `创作工具星图-v1.6.0-win64.zip`。自检：print 初始禁用+纳入 dirty+生成后启用；首页含"9 条工作流支线""点击即调用"；release 只剩 4 个英文名包。[达成]

| 完整性 | 折叠状态重绘丢失；print 样式遗漏；使用说明漏 5 脚本；build_manifest 单向校验 | 状态数据化回放；打印只留正文；文档路径双给；清单双向校验 |
| 可读性 | 首页卡片停留旧版；文档数字失真（22/17 矛盾、六轮120轮）；CHANGELOG 断言史矛盾 | 首页反映当前能力；数字全部对齐（25 条/8 轮160轮）；断言口径脚注 |
| 性能 | 搜索无 debounce 全量重建；localStorage 冗余无去重 | 150ms debounce；内容签名去重 + 截断提示 |
| 边界情况 | 畸形 localStorage 数据崩溃；无 Python 版本检查；无日志轮转；中文路径 bat 写坏 | 类型规范化 + try/catch；版本门槛；1MB 轮转；UTF-8 编码 |
| 一致性 | 探测竞态旧结果覆盖新；README 版本检查静默跳过；版本归属错标 | 互斥锁+代际淘汰；README 双路径显式 FAIL；版本归属归位 |
| 工程门禁 | selftest 缺文件抛 traceback；断言 23 条 | 结构化 FAIL；25 条断言；双向清单校验 |

**核心需求稳定性**：9 条工作流支线、顶部需求选择、工具点击调用、任务包流入执行台——20 轮全程未变，终检确认。

**本轮最值得记的三件事**：
1. **语义一致性比代码正确性更隐蔽**：轮 1 的"第3节说用、第4节删掉"不是任何一行代码报错，而是数据流（roles vs stageTools）的语义断裂——深度审查的价值恰在于此。
2. **状态要数据化，别寄存在 DOM 上**：轮 5/8 证明，把 pending、折叠这类状态存在 DOM 节点里，任何重绘都会丢失；提升为数据模型后重绘无害。
3. **质量门禁本身也要被审查**：轮 13/14/15 修的都是"自检/清单工具自己有盲区"——守护者也需要被守护。

**验证方式**：全程未运行 exe、未弹系统浏览器；HTML 经内置浏览器预览；逻辑用 node mock DOM（12 个专项测试脚本）；HTTP 用临时端口实跑；脚本用 PS Parser 语法校验；清单用故意投毒实测拒绝；日志用 1MB 预置实测轮转。
