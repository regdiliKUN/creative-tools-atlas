# 创作工具星图 · 第七轮迭代记录（v1.6.2 → v1.7.0）

> 20 轮迭代，每轮围绕至少一个质量维度做实质改进，均基于两份独立深度审查发现的真实缺陷。
> 核心需求与整体结构全程稳定，无凑数式修改。基线 v1.6.2，终版 v1.7.0。

## 迭代方式

动工前对产出物做了两轮独立代码审查（只读），共发现 28 个真实缺陷：
- 审查 A（studio.html）：12 个问题，含 2 个确定性严重 bug（清空按钮崩溃、历史载入执行台失效）；
- 审查 B（工具桥/自检/文档）：16 个问题，含 1 个安全漏洞（通配 CORS 可跨站触发安装）。

20 轮即围绕这些真实问题逐项修复，并在过程中由自检套件反向抓到 1 个我自己的过度改造（轮19）。

---

## 阶段 A · 正确性与安全（轮 1-8）

**轮 1 · 正确性** — 修复「清空表单」引用不存在的 `#goals` 元素导致 TypeError，异常使后续重置全成死代码。
改动：删除历史残留行，直接 `selectedWf.clear()`。自检：node 模拟点击，无异常、工作流已清空。[达成]

**轮 2 · 正确性** — 历史载入丢失 `last.p`，执行台空白且此后桥状态刷新永远不更新。
改动：保存时持久化 `p/goals/style`；载入时恢复 `last.p` 并按工作流重绘执行台；旧记录退化为 goals 兼容渲染。自检：生成→保存→载入，执行台非空且含对应支线。[达成]

**轮 3 · 完整性** — 清空不复位 `last`/输出区/操作按钮，状态自相矛盾。
改动：抽出 `resetOutput()`，统一复位 last=null、输出提示、四个按钮禁用。自检：清空后按钮全禁用、输出复位。[达成]

**轮 4 · 一致性** — `promptKind` 是死字段，选 CAD/像素支线仍生成"角色设定图"提示词。
改动：`promptPack()` 按工作流 promptKind 分派 7 套专属正负提示词模板。自检：9 条支线覆盖 7 种模板，各不相同。[达成]

**轮 5 · 一致性** — `steps()` 无条件硬编码"装机 Krita / 起稿"，污染所有非角色工作流。
改动：执行清单改从选中工作流 stages 生成（与任务包第3节、执行台同源）；旧任务包走 goals 兼容。自检：pixel/cad 清单不再含 Krita，含各自专用工具。[达成]

**轮 6 · 正确性** — `downgraded` 收录全部工具（why 恒真），任务包一边标"首选 ComfyUI"一边说它"已降级别开工"。
改动：只收录真正因显存/许可被降级、且不在首选/备选中的工具；标题改准确。自检：首选未出现在降级列表，真限制项（Unique3D 等）被列出。[达成]

**轮 7 · 正确性/边界** — `pip_installed()` 不检查 returncode，CLI 工具全误报"已安装"；`launch()` 无 cli 分支导致点了必失败。
改动：检查 returncode；launch 增 cli/suite 明确语义；前端对 cli/suite 渲染"命令行/需配置"标签而非"启动"。自检：假模块返回 False、sys 返回 True、cli launch 给出说明。[达成]

**轮 8 · 安全性** — 工具桥通配 CORS + 零来源校验，任意网页可 fetch 触发本机 winget 安装（真攻击面）。
改动：Origin 白名单（仅 file:// 的 null 与本机 http/https）+ Host 校验挡 DNS rebinding；CORS 不再用 `*`；统一 `_guard()` 入口。自检：7 场景（file/本地预览/恶意站/rebinding/curl）全部符合预期。[达成]

## 阶段 B · 完整性与边界（轮 9-14）

**轮 9 · 正确性** — 通用工具（roles 空）按质量分压过专用工具，pixel 工作流首选变成 Krita 而非 Aseprite。
改动：rankTools 给精准命中 goals 的工具减 30、通用工具加 5。自检：pixel 首选纠正为 Aseprite，to3d 仍 TRELLIS 居首（效果优先不变）。[达成]

**轮 10 · 一致性** — 多选工作流的顺序被忽略（保存了 Set 顺序却按定义顺序渲染），违背"依次列出"承诺。
改动：buildPackage/renderExec 改按 `p.workflows.map` 顺序。自检：反序多选，任务包与执行台顺序均跟随。[达成]

**轮 11 · 边界/正确性** — Markdown 上下文误用 HTML 转义（导出出现 `&amp;`）；web 工具"打开"按钮被 finally 复位成"启动"。
改动：移除 Markdown 生成中的 esc()；按钮保存 origText 并在 finally 恢复。自检：buildPackage 段 esc() 残留 0，origText 逻辑就位。[达成]

**轮 12 · 边界/健壮性** — localStorage 被篡改成非数组对象导致 renderHist 崩溃；旧浏览器无 `AbortSignal.timeout` 使工具桥永久离线、所有按钮消失。
改动：`getHist()` 加 Array.isArray；`timeoutFetch()` 用 AbortController 兜底。自检：localStorage={} 返回 []，无 timeout API 环境 fetch 仍可用。[达成]

**轮 13 · 边界/安全** — `-Stop` 只按端口 kill 会误杀无关进程；`Invoke-Expression` 拼路径遇空格/`$` 出错；注册表白名单漏 OpenSCAD/MeshLab/OpenToonz/Aseprite。
改动：Stop 前校验进程名含 python 且命令行含 tool-bridge.py；去掉 Invoke-Expression 改直接引号参数；注册表匹配改用工具 reg 名+扩展关键字。自检：PS 纯 ASCII、无 Invoke-Expression、进程校验就位、白名单含四工具。[达成]

**轮 14 · 完整性/可信度** — build_manifest 缺失文件静默写"缺失"仍退出 0；verify 的正则跳过缺失行；selftest 后缀白名单漏 .ps1/.py——三者形成"文件缺失却报完好"的漏检闭环。
改动：build_manifest 缺失即 exit(1)；verify 增"大小列非数字"检测；selftest 改全量扫描（排除 _internal/日志）。自检：交付文件扫描 16→24 项，全绿；期间我发现编辑一度破坏了 diagnose.ps1 语法，靠 PS Parser 发现并修复——这正是轮16 要补的自检盲区。[达成 + 现场纠错]

## 阶段 C · 可读性与一致性（轮 15-20）

**轮 15 · 一致性** — winget 中文系统"已安装"匹配不到英文串而误报失败；pip 10分钟超时却提示"15分钟"。
改动：returncode 为主 + 中英双语识别；按分支给正确超时文案。自检：中文识别串与分支文案就位。[达成]

**轮 16 · 一致性/完整性** — 版本漂移（README 仍 v1.6.1/v1.6.0、使用说明 v1.0→v1.5）；README 不在版本断言内；自检不解析 PS 语法（轮14 语法错潜伏的盲区）。
改动：修正文档版本；README 纳入版本检查；新增 `check_ps_braces()` 静态括号平衡断言。自检：版本一致性六处对齐；新增断言后 23/23 全绿。[达成]

**轮 17 · 可读性** — README 目录树漏列 4 个新文件（tool-bridge.py 等）；开发者按目录找不到本地工具链组件。
改动：补全目录树 4 项。自检：README 12 个链接零失效。[达成]

**轮 18 · 可读性/完整性** — 使用说明缺工具桥启动指引，承诺"点击即启动"却没给前置步骤，用户按说明会卡在"桥未连接"。
改动：新增「本地工具桥·点击即启动的前置步骤」章节，含完整命令、就绪标志、安全关闭方式。自检：文档含章节与命令。[达成]

**轮 19 · 可读性/无障碍（含自我纠错）** — 技法工具渲染成 `href="#"` 空链接，键盘/读屏点按无反馈。
改动：改为带 title 说明的非交互 `<span>`。期间我一度把 main landmark 与 h4 aria-level 也改了，被自检当场拦截（22/23 FAIL）——这两处是项目跨页无障碍约定，不该为"我觉得更语义化"破坏，遂回滚，只保留空链接修复。自检：无障碍断言全过。[达成 + 被自检纠正过度改造]

**轮 20 · 性能/健壮性** — ThreadingHTTPServer 多线程日志无锁会串字；端口占用直接崩栈；双击安装并发跑两个进程。
改动：日志加 threading.Lock；bind 捕 OSError 给友好提示并引导 -Stop；install 按 tid 加锁去重。自检：并发写 50 行零丢失；锁/异常处理/去重全部就位。[达成]

|---|---|---|
| 正确性 | 清空按钮崩溃、历史载入执行台失效、CLI 工具误报已装、downgraded 自相矛盾 | 全部修复；20 轮 node 场景测试逐项验证；数据流 selectedWf→profile→任务包/执行台一致 |
| 完整性 | 提示词不随工作流变、清单缺失可报完好、文档漏 4 文件 | 7 套专属提示词；清单缺失即失败；工具桥指引与目录树齐全；自检 22→23 条 |
| 可读性 | 技法空链接无反馈、README 版本漂移、目录树不全 | 技法改说明性 span；文档版本六处对齐；目录树完整、链接零失效 |

| 一致性 | 多选顺序丢失、执行清单污染、winget 中文误判 | 选择顺序全程保留；清单与支线同源；中英双语识别 |

**核心需求稳定性**：9 条工作流支线、顶部需求选择、工具点击调用、任务包流入执行台——20 轮全程未变，终检确认。

**验证方式**：全程未运行 exe、未弹系统浏览器；HTML 经内置浏览器预览；逻辑用 node mock DOM，安全用白名单单测，脚本用 PS Parser 语法校验。

**本轮最值得记的两件事**：
1. 深度审查发现的两个确定性严重 bug（清空崩溃、历史载入失效）都是上一轮"功能上线"时没测到的——**新功能的回归测试必须覆盖清空/载入这类次要路径**。
2. 自检套件两次反向抓到我自己的改动错误（轮14 PS 语法、轮19 无障碍约定）——**质量守护体系的价值，在于它连作者的过度改造也拦得住**。
