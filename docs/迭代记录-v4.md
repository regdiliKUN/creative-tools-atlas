# 创作工具星图 · 第四轮迭代记录（v1.3.0 → v1.4.0）

> 基线：v1.3.0（第三轮 20 轮迭代后的版本）
> 约束：验证不运行 exe、不弹系统浏览器，全部用 WorkBuddy 内置浏览器预览 HTML。
> 锁定项：exe 启动方式、I 盘落位 `I:\workbuddy\创作工具星图\`、桌面快捷方式精确指向 exe。

## 本轮侦察发现（待修的真实缺陷）

1. **清单漏覆盖**：三份迭代记录（`迭代记录.md`/`-v2`/`-v3`）是交付文档却不在 MANIFEST 里，清单名不副实。
2. **锁文件名全局固定**：`creator-atlas-app.lock` 在多用户/多会话共享临时目录时会互相干扰；且未校验锁内 PID 是否存活。
3. **HTML 语义化缺口**：三页均无 `<main>` 标签，首页连 `<header>/<footer>/<nav>` 都缺；屏幕阅读器无法快速定位主内容。
4. **其他待挖**：继续在迭代中逐项核查。

## 迭代日志

### 阶段 A：启动器与清单正确性（轮 1-7）

**轮 1 · 正确性/边界** — 锁文件名按用户名隔离（多用户共享临时目录互不干扰）；新增 `_pid_alive()`，读取锁内 PID，进程已死则忽略陈旧锁立即自愈，不再死等 TTL。
自检：当前 PID 判活 True、假 PID False、PID≤0 False；首次 True、连点 False；编译通过。[达成]

**轮 2 · 完整性** — 三份迭代记录纳入 MANIFEST（从 build_manifest.py 根本配置改）。
自检：清单 10→13 项，三份记录全部命中。[达成]

**轮 3 · 正确性（含自我纠错）** — 给校验器加"哈希前缀 ≥8 位"断言，防止清单被篡改成短哈希削弱检测。首次加入时**中文注释破坏了 .ps1 纯 ASCII 铁律**（PowerShell 5.1 按 ANSI 读导致花括号解析错误），定位后改英文注释，并用字节级断言确认脚本纯 ASCII。
自检：非 ASCII 字节数 0；校验器正常运行 `CHECKED=13 / VERIFY_OK`。[达成 + 捕获并修复自身失误]

**轮 4 · 一致性/可读性** — 把".ps1 必须纯 ASCII"的维护注意写进使用说明，从文档层面固化教训（而非往校验器塞逻辑，避免过度工程）。
自检：维护注意命中。[达成]

**轮 5 · 边界情况（验证轮）** — 检查 PID 探测依赖的 `ctypes` 是否被 PyInstaller 正确打包，排除"exe 里 PID 判活因缺模块崩溃"的隐患。
结论：`_ctypes.pyd` 在包内、xref 记录了 ctypes 依赖，打包链完整。验证轮无改动。[达成（验证）]

**轮 6 · 一致性** — 前台重建 exe（1,836,591 B）使源码落地；不运行。
自检：包内 exe 与 dist 字节一致。[达成]

**轮 7 · 一致性** — 版本 v1.3.0 → v1.4.0，从说明/首页/清单生成脚本三处同步（生成脚本层面根治）。
自检：三处版本 grep 唯一 v1.4.0。[达成]
